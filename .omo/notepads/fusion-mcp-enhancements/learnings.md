## Wave 1 / Todos 3-6: Dimensioning tools (get_physical_properties, measure_angle, get_oriented_bounding_box, inspect_body)
- `PhysicalProperties.getXYZMomentsOfInertia()` returns a **7-tuple** `(True, Ixx, Iyy, Izz, Ixy, Iyz, Ixz)` — leading success flag; moments are about the **component origin**, NOT the CoM (verified on centered 5×3×2 box: Ixx=0.490625, Iyy=0.804625, Izz=0.66725, products 0; about-origin values = CoM values + m*d² via parallel axis).
- Principal moment MAGNITUDES come from `getPrincipalMomentsOfInertia()` → `(True, I1, I2, I3)` (about CoM: 0.255125/0.569125/0.66725 for that box). `getPrincipalAxes()` → `(True, axis1, axis2, axis3)` returns ONLY the three principal axis VECTORS. `getRotationToPrincipal()` → `(True, angleX, angleY, angleZ)`. All four methods are success-flag-prefixed tuples — strip index 0.
- `SurfaceEvaluator.getNormalAtParameter(parameter)` takes exactly ONE positional argument (the Point2D parameter). Get it first via `evaluator.getParameterAtPoint(face.pointOnFace)` → `(bool, Point2D)`. Do NOT pass (point, parameter) — 3-arg call raises "takes 2 positional arguments but 3 were given".
- `face.geometry.classType()` returns prefixed names like `adsk::core::Cylinder` / `adsk::core::Plane`; `edge.geometry.classType()` → `adsk::core::Circle3D` / `adsk::core::Line3D`; `vertex.geometry.classType()` → `adsk::core::Point3D`. Split on "::" and take [-1] for the short class name.
- `face.geometry.radius` exposes cylinder radius (6.0 ✓); `edge.geometry.radius` exposes circle radius (6.0 ✓); circle edge length = 2πr (37.699 ✓).
- `app.measureManager.getOrientedBoundingBox(BRepBody, Vector3D lengthVector, Vector3D widthVector)` — confirmed 3 required args, accepts the body directly, returns `OrientedBoundingBox3D` with `.centerPoint/.length/.width/.height`. Length/width follow the given vectors; height is the perpendicular third direction (length=X,width=Y → 5×3×2 on the test box; length=Y,width=Z → 3×2×5).
- `app.measureManager.measureAngle(ent1, ent2)` works for face-face and edge-edge, returns `MeasureResults.value` in **radians** (adjacent box faces → 90.0°; parallel faces → 0.0°). Body-body specifiers are rejected pre-call with a faces/edges hint.
- `_find_body` silently falls back to body 0 for out-of-range indices (body="999" returns body 0!). The new `_require_body(root, ref)` helper raises `Body 'X' not found.` instead — all 4 new dimensioning tools use it so failure QA behaves correctly.
- Fresh-module QA gotcha: `mod._get_physical_properties(root, {...})` fails with `'NoneType' object has no attribute 'measureManager'` unless `mod.app = app` is set first (module-level `app` is None outside `run()`). With `mod.app = app`, `mod._process_command({"command": ..., "params": ...})` exercises the FULL dispatch path end-to-end without syncing the add-in copy.
- Default Fusion material density = 0.00785 kg/cm³ (steel); mass = volume × 0.00785 (30 cm³ → 0.2355 kg).

## Wave 2 / Todo 13: CSG translator (mcp_server/scad_translator.py)
- **Evaluator positional args use INT dict keys** (`params["args"] == {0: [...], 1: [...]}`), while the .csg fallback walker builds STRING keys (`{"0": ...}`). Any param lookup that must work on both paths has to check `"0" in args` AND `0 in args`. This bug silently broke BOSL2 identity-multmatrix collapse (cuboid/cyl stayed wrapped in multmatrix) until fixed in `_sanitize_node` + `_transform_vector` + `_transform_matrix`.
- BOSL2 `diff() cuboid(30) { edge_profile(TOP) mask2d_roundover(r=5); }` resolves to `union → difference → (cube + 4× translate→multmatrix→linear_extrude→mirror→multmatrix)` as difference[0], plus TWO more top-level union children (4× ...→mirror→polygon real extrudes, 4× ghost empty extrudes). 12 linear_extrude nodes total; empty-child extrudes return [] harmlessly. All ghost wrappers are identity-multmatrix + empty, so they translate to nothing.
- Multmatrix decomposition `M = T·R·S` uses polar decomposition of the 3×3 linear part via `sqrt(AᵀA)` (Jacobi symmetric eigendecomposition). Scale hits the first COLUMN of R in `R·S` order — a test matrix written as `[[0,-2],[2,0]]` actually encodes scale(2,2,1), NOT scale(2,1,1); Rz(90°) is `[[0,-1,0],[1,0,0],[0,0,1]]` (rot[0][1] = -1). Verified: `_decompose_multmatrix([[0,-1,0,10],[2,0,0,20],[0,0,1,30],[0,0,0,1]])` → translation [10,20,30], scales [2,1,1], rotation Rz(90°).
- Two-phase design verified headless: `translate_to_fusion_commands` runs `_validate_tree` (pure, no adsk/root) BEFORE `_import_adsk()`. A hull/banana tree raises `UnsupportedSCADNodeError` with a Trap-stub root that asserts on ANY attribute access (stub never touched); a valid cube tree instead raises the "adsk is not available" RuntimeError — proving validation passed and only then adsk import failed.
- QA of polyhedron params is headless-testable via pure helpers: `_polyhedron_mesh` normalizes evaluator shape `{verts, tri_arr}` and .csg shape `{points, faces}` (faces fan-triangulated); `_is_loftable` detects the 2-ring prism case. Full mesh/live body creation deferred to Todo 14 (needs adsk).
- OpenSCAD 2021.01 binary on Windows rejects UTF-8 BOM .scad files with "Parser error: syntax error ... line 1". Files must be written BOM-free (Write tool or `open(...,'wb')`), NOT via PowerShell `Set-Content -Encoding UTF8` (adds BOM in PS 5.1).

## Wave 2 / Todos 7-9: File import tools (import_cad_file, import_mesh_file, import_sketch_file)
- `app.importManager.importToTarget(options, target)` RAISES `RuntimeError: 2 : InternalValidationError : results` from `_core.ImportManager_importToTarget` even when the import fully succeeds (verified live: STEP import raised it but root.bRepBodies.count went 0→2). The reliable success signal is geometry appearing in the target — check the count delta (bodies/sketches/curves) and treat an exception as failure ONLY if nothing appeared. Do NOT trust exception-free calls or return values as success.
- importToTarget target semantics differ by format: STEP/SAT/SMT/IGES/F3D and DXF2D import into a **Component** (root works); SVG requires a **Sketch** target — `importToTarget(svg_options, root)` fails with `3 : invalid argument target, expected a sketch`. Create the sketch first (`root.sketches.add(root.xYConstructionPlane)`), then import into it.
- `root.meshBodies.add(path, units, base_feature)` returns a **MeshBodyList**, not a MeshBody — grab the body via `result.item(result.count - 1).name`. In a parametric doc, a fresh document's `root.features.baseFeatures` has count 0 → `.add()` first; then `startEdit()` → `add(path, unit, base_feature)` → `finishEdit()` produces a proper timeline entry (verified: timeline shows BaseFeature → "Elemento de malla base").
- `app.activeDocument.isSaved` exists (False for a never-saved doc) and `Design.designType == DesignTypes.ParametricDesignType` (enum value 1) — both usable to branch direct vs parametric mesh import.
- The save-first retry (B-requirement) never fired in practice: STEP import raised InternalValidationError (handled as success via count check), never a save-related error. Kept as defense-in-depth.
- as_component=True: `occ = root.occurrences.addNewComponent(adsk.core.Matrix3D.create())`, import into `occ.component`, then count `target.bRepBodies.count` / `target.meshBodies.count`. Verified for both STEP and STL.
- DXF 2D import (`createDXF2DImportOptions(path, plane_entity)`) works cleanly with a minimal LINE-entity DXF fixture, imports a sketch into root; plane selects XY/XZ/YZ construction plane.

## Wave 2 / Todos 15-16: 2D primitives + extrudes, transform chain (scad_translator.py)
- Committed as `7b27e48` (Todo 15) and `32f98f3` (Todo 16) — each staged ONLY `mcp_server/scad_translator.py` by explicit path (untracked `.omo/`/`.sisyphus/` left alone). Todo 15: 362 insertions/25 deletions; Todo 16: 72/7.
- Evaluator node shapes verified empirically: `square([10,20])` → `size:[10,20]`, `center:false`; `square(10)` → `size:[10,10]`, `center:true`; `circle(r=5)` → `r:5`, `segs:16`; `circle(d=8)` → **evaluator resolves d→r=4** with `segs:13` (Δr≈1.52°); `polygon(points=...)` → key is **`pts`** with `paths:null` (NOT `points`). So `_eval_2d_primitive` reads `pts` and falls back to `points` for .csg input. BOSL2 `rect([10,20])` → square node, `regular_ngon` → polygon, `mask2d_roundover(r=5)` → polygon (R≈0.707r fillet fan), `ring(id=,od=)` → ERROR (modern BOSL2 ring uses `r1`/`r2`).
- linear_extrude evaluator node: `height`, `center`, `twist`, `scale_top` (evaluator uses `scale_top`, not `scale`); rotate_extrude node: `angle`. `rotate_extrude(angle=180) translate(...) circle(...)` nests translate→circle under rotate_extrude — handled by drawing all 2D children into the XZ sketch with `_compose_2d_transform` applied (identity multmatrix entries collapse). BOSL2 `diff()` resolves to `union→difference` (see Todo 13 learnings) — `_validate_tree` must recurse into children of supported parents; 2D primitives anywhere else raise `UnsupportedSCADNodeError` ("requires linear_extrude or rotate_extrude parent").
- .csg fallback (2026.08.01 binary) BAKES transforms: translate/rotate/scale become nested `multmatrix` nodes (row-major 16-list), so `_csg_ast_to_node` produces no translate/rotate/scale nodes from .csg — only `multmatrix`. `_decompose_multmatrix` (Todo 13) turns them back into translate/rotate/scale during eval. .csg polygon: `points` (converted to `pts` by `_sanitize_node`), `paths:undef→null`, `convexity`. .csg circle `r`/square `size`+`center` shapes match the evaluator's sanitized form.
- .csg from OLD OpenSCAD (≤2021.01) emits NAMED args for transforms: `translate(v=...)`, `rotate(a=...)`, `scale(v=...)`, `multmatrix(m=...)`. `_transform_vector`/`_transform_matrix` now accept `v`/`a`/`m` named params in addition to `"0"`/`0` keys — required so old-.csg transforms aren't silently dropped.
- `_rotation_matrix` semantics: `preTransformBy` called for X, then Y, then Z → resulting matrix `M = Rz·Ry·Rx`. Verified pure-math: `rotate([0,0,90])` maps (1,0,0)→(0,1,0); `rotate([90,45,30])` = Rz(30)·Ry(45)·Rx(90); chain `translate([5,0,0]) rotate([0,0,90]) cube([5,5,5])` → final bbox [0,0,0]..[5,5,5] (cube [0..5]³ Rz-rotated to [-5,0,0]..[0,5,5], then +5x). Matches OpenSCAD docs "rotate([rx,ry,rz]) == rotate(rz,[0,0,1]) rotate(ry,[0,1,0]) rotate(rx,[1,0,0])".
- rotate angle validation (`_validate_rotate`): scalar → Z-axis; 1-vector `[a]` → Z-axis; 3-vector → [rx,ry,rz]; empty/no angle → identity; anything else (string, mixed vec, 2-vector) → `UnsupportedSCADNodeError` during the pure validation phase. `_rotate_angles` normalizes scalar/1-vec to `[0,0,a]` for the matrix path.
- Extrude profile technique: draw profile sketches on XY (linear) / XZ (rotate) plane, collect `SketchProfile`s from `profileLoops`, then create features via an `adsk.fusion.ObjectCollection` of profiles — matches FusionMCP.py `_extrude`/`_revolve` reference (revolve: `setAngleExtent(False, radians)`). `_profiles_avoiding_axis` drops profiles whose `fitPoint` lies ON the revolution axis line (degenerate rings) — required for `rotate_extrude(angle=180) translate(...) circle(...)`.
