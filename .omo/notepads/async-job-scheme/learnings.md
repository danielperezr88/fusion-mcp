## Task 1 (2026-08-05) - mcp_server/jobs.py + tests/test_jobs.py
- Created `mcp_server/jobs.py` (~90 LOC, stdlib only: `threading`, `uuid`, `time`): `_JOBS: dict[str, dict]`, `_LOCK = threading.Lock()`, `MAX_JOBS = 64`, `JOB_TTL = 3600.0`; public API `launch_job(fn, *args, **kwargs) -> str`, `get_job(job_id) -> dict | None`, `prune()`; private `_run(job_id, fn, args, kwargs)`.
- Locking convention: `prune()` assumes the caller holds `_LOCK` (it is NOT reentrant-safe to call from `launch_job`'s `with _LOCK:` block if it acquired the lock itself). Spec has `launch_job` call `prune()` under the lock AND describes `prune()` as running under `_LOCK` — the only consistent reading is prune is lock-free. Documented in the module docstring. Direct calls (tests) are safe only when no other thread mutates `_JOBS`.
- Eviction: `while len(_JOBS) > MAX_JOBS`, drop the finished record with the smallest `finished` timestamp; `break` when only running records remain (running NEVER evicted, cap may exceed 64 transiently).
- Import convention: `tests/conftest.py` already inserts the repo root on `sys.path` (mcp_server is a namespace package, no `__init__.py`), so `import mcp_server.jobs as jobs` works with NO sys.path manipulation in the test file (same as `test_workflow_guide.py`'s `from mcp_server.workflow_guide import ...`).
- TEST-DESIGN GOTCHA (fixed a real failing test): in the LRU-cap test, launching 66 fast `lambda: None` jobs in a loop lets early ones COMPLETE mid-launch; the next `launch_job`'s internal `prune()` then evicts them as oldest-finished before the test polls them (`get_job` → None). Fix: gate the 66 "fast" jobs on a `threading.Event` so none finish during the launch loop, set the gate after all launches, then `_wait_for` each. This matches the acceptance criterion "launch 70, let 66 finish, keep 4 running" deterministically.
- Deterministic "still running" jobs: a job body blocked on `Event.wait(timeout=30)` stays `running` with no wall-clock dependence; release + `_wait_for("completed")` for clean teardown.
- 8 tests: unique-running, slow-fn→completed(42), raising fn→error("division by zero"), unknown→None, TTL expiry (fabricate `finished = now - JOB_TTL - 5` then `prune()`), recently-finished survives prune, LRU cap (≤64 + all 4 running present), 20-thread barrier concurrency (20 unique ids, all completed).
