**What you'll get:** A hardened mesh face decomposition that produces more reliable planar faces across any input tolerance, plus two new tools — one that builds a graph of how faces connect (adjacency, parallelism, containment, solid-degree relationships) and stores it in an embedded query engine, another that lets the agent query that graph with SQL to plan a stepwise rebuild of any arbitrarily complex solid. The workstream analysis (which face is the base, how to order the rebuild operations) is computed automatically and stored alongside the graph. Hole classification is hardened, all tolerance constants are unified behind one model, and the agent gets presets to match production CAD behavior.

**Why this approach:** The core insight from the research tracking down why our first two rounds failed is that tolerance brittleness and silent failures are the root cause. Phase 1 fixes those at the source (quantization-derived tolerances, connectivity-constrained grouping, non-manifold reporting). Phase 2 builds the graph the agent needs to plan rebuilds — but instead of dumping the whole graph as JSON (which breaks at arbitrary complexity), it persists to an embedded SQL engine so the agent queries incrementally, never receiving more than it asked for. Phase 3 enriches the graph with workstream intelligence computed once at build time. Phase 4 hardens the remaining edges cases discovered in the literature survey.

**What it will NOT do:** No changes to the SCAD translator. No external database servers (DuckDB is embedded in-process). No breaking changes to existing face decomposition output — everything is additive. No full voxelization implementation (just detection and warning).

**Effort:** Large — 15 implementation tasks across 4 sequential phases
**Risk:** Medium — R-2 (connectivity-constrained grouping) is the highest-risk change (modifies the core grouping algorithm); DuckDB is a new compiled dependency but has verified cp3.14 wheels and is MIT-licensed
**Decisions to sanity-check:** DuckDB over NetworkX-only query DSL (you chose this); connectivity-constrained grouping as primary with global fallback; quantization-step detection with k=3 multiplier; R-8 voxel/SDF is detection-only.

## Scope
### Must have
- R-1: Quantization-step-derived weld/snap tolerances replacing extent-based magic constants
- R-2: Connectivity-constrained planar grouping (primary) with global grouping fallback
- R-3: O(n) spatial-hash snap replacing O(n²) pairwise union-find
- R-4: Per-face residual non-manifold edge reporting (warning field in decompose output)
- New `mcp_server/mesh_graph.py`: NetworkX graph construction over decompose output with all 4 node labels + 10 edge types per RESEARCH-B taxonomy
- DuckDB persistence: `_persist_to_duckdb()` storing nodes+edges tables with algorithm results as columns
- MCP tool `structure_graph(mesh, units)`: decompose→build→persist→return summary JSON (NOT full graph)
- MCP tool `query_structure_graph(mesh, sql)`: execute SQL against persisted DuckDB, return JSON rows
- Workstream: base-face composite scoring, unit classification, dependency DAG ordering computed at build time, stored as DuckDB columns
- R-5: hardened hole classification (opposite signed area + no centroid; winding number for ambiguous)
- R-6: unified tolerance model (`_ToleranceConfig(quant_step, extent)` dataclass)
- R-7: plane-fit residual in grouping predicate
- R-8: voxel/SDF fallback detection + warning propagated to structure_graph summary
- R-9: expose offset_tol/snap_tol/simp_tol as optional params + presets on decompose_mesh_faces, wired through analyze_mesh and structure_graph tools
- R-10: trimesh.facets cross-check diagnostic in tests
- Headless pytest tests for every function added or modified

### Must NOT have (guardrails, anti-slop, scope boundaries)
- NO changes to `mcp_server/scad_translator.py`
- NO external graph database server (DuckDB is embedded in-process; no Neo4j/kuzu/DuckDB-as-service)
- NO server-side vision API calls
- NO breaking changes to existing `decompose_mesh_faces` output keys (additive only — new keys alongside existing ones)
- NO numpy dependency in `mesh_graph.py` (numpy stays in mesh_analysis.py; mesh_graph.py uses duckdb + networkx only)
- NO full voxelization/SDF mesh repair implementation (R-8 is detection + warning only)
- NO separate query MCP tools beyond `query_structure_graph(mesh, sql)` (SQL is the query language)
- NO multi-body segmentation or multi-mesh analysis
- NO git commits by subagents
