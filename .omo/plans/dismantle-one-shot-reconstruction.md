# dismantle-one-shot-reconstruction - Work Plan

## TL;DR (For humans)

**What you'll get.** Two 1-shot reconstruction MCP tools (`reconstruct_mesh`, `reconstruct_from_faces`) and their backend strategy emissions (`build_csg_tree`, `_prismatic / _csg_decompose / _grow_regions / ...`, the synthetic strategy assumptions and unit-type labels inside the foundational tool output) are removed from `fusion_server.py`, `mesh_csg.py`, `mesh_analysis.py`, `mesh_graph.py`, and `workflow_guide.py`. Five files in `mcp_server/` are edited; 2 test files deleted; 4 test files updated + 1 refactored; `README.md` updated. Single atomic commit on `master`. The remaining "foundational toolset" (`analyze_mesh`, `slice_mesh`, `structure_graph`, `query_structure_graph`, `compare_mesh_to_brep`, `select_parameter_schema`, `annotate_mesh_parameters`, `review_reconstruction`, `get_workflow_guide`, plus the OpenSCAD pipeline `run_scad` / `update_scad_body` / `create_from_scad` and the standard sketch/feature toolkit) is preserved untouched in behavior — ready for an agent (in the next iteration) to attempt the reconstruction from primitives rather than from a one-shot server-side path that the user observed doesn't fit hollow thin-walled parts with shelves and towers.

**Why this approach.** The vision-guided demo (REJECT verdict) showed the 1-shot tools collapse complex hollow geometries to flat extrusions: the agent never had a real chance to reconstruct iteratively because the foundational tools were already pre-routed through a forced single-trip strategy. "Surgical removal" honors two user directives simultaneously: keep useful Python primitives (`compute_revolved_profile`, `scale_tree`, euler / CSG-node helpers) as importable code; strip the assumption-baked text ("MODEL ACTION: call reconstruct_mesh again...") from the kept tools' return envelopes. The salvage boundary the user wanted — "don't throw away useful code" — is honored by preserving those primitives in `mesh_csg.py` even though no MCP tool wraps them yet; future exposure is a separate iteration.

**What it will NOT do.** No new MCP tools are introduced (e.g. no `extract_revolve_profile`). No replacement for the 1-shot `reconstruct_mesh` — the user retests the reconstruction themselves next. No changes to `scad_translator.py`, `bundle.py`, the OpenSCAD pipeline, the add-in `FusionMCP.py`, or `import_*` tools. No change to the function contracts of `analyze_mesh` (only the deleted `recommended_strategy` field), `compare_mesh_to_brep`, `structure_graph` (only deleted `unit_types` + `rebuild_order` workstream keys), `query_structure_graph`, `slice_mesh`, `select_parameter_schema`. No `git rebase` or force push. The 4 ambiguous tools (annotate, select_schema, review_reconstruction, get_workflow_guide) stay; only the prescribed-workflow text gets stripped, and the workflow_guide GUID gets a placeholder entry where reconstruct_mesh used to be.

**Effort.** ~3–4 implementation waves (server edit; backend slim + analysis/graph strips; consumer-set-of-tests refactor; README). ~9 implementation todos + 4 final-wave verifications (F1 plan compliance, F2 code quality, F3 real manual QA vs live Fusion 360, F4 scope fidelity). Each todo ships evidence under `.omo/evidence/dismantle-T<n>-*.log`; one atomic commit lands at the end once F1–F4 all APPROVE.

**Risk.** Highest risk: `test_mesh_to_brep_live.py` + `test_review_reconstruction_live.py` import `mesh_csg.build_csg_tree` directly and hand-roll a tree fed into the add-in's `create_from_csg_tree`. After `build_csg_tree` is removed, those tests MUST substitute a hand-rolled minimal CSG tree (literal cube node) OR replace the CSG-tree approach with `create_from_scad(code="cube([10,10,10]);")` (independent of mesh_csg.py — proven by `test_openscad_live.py`). The plan T7 specifies the substitution; F3 verifies the actual `compare_mesh_to_brep` flow still produces real numbers via this substituted path. Mitigating the risk: fallback to the proven `create_from_scad` substitution if the hand-rolled tree path doesn't compile in Fusion.

**Decisions.**

- **D1 — Surgical scope for the 4 ambiguous tools (KEEP + STRIP):** preserves useful agent tooling (vision facts, parameter bindings, side-by-side QA images, the workflow reference) while removing the prescribed-workflow-pointer that told the agent to call `reconstruct_mesh` again. Honors "don't throw away useful code". Won by user answer to fork question.
- **D2 — Salvage primitives in `mesh_csg.py` (slimmed):** `compute_revolved_profile`, `scale_tree`, `_euler_angles_from_rotation`, `_primitive_node`, plus the geometric helpers — remain importable Python even though no MCP tool wraps them. Won by "don't throw away useful code" directive.
- **D3 — Drop `recommended_strategy` from `analyze_mesh` output:** the field told the agent WHICH 1-shot strategy to use. Removing it leaves the raw `primitive_hints` (box_confidence / cylinder / plane_regions) so the agent decides. Won by "tools don't make assumptions beyond surfaces + graph".
- **D4 — Drop `_classify_units / _build_dependency_order` from `mesh_graph.py`:** `unit_types` (base/hole/fillet/...) and the `rebuild_order` DAG-order labeling are interpretive 1-shot scaffolding for csg_decompose, not surface-graph relationships. KEEP `_score_base_faces` + `base_face_per_component` (topological). Won by the same principle.
- **D5 — Delete `NotPrismaticError` + `UnsupportedStrategyError` + `_CSG_STRATEGIES` from `mesh_csg.py`:** no consumers after dismantle.
- **D6 — Preserve `scad_translator.py` + OpenSCAD pipeline (`run_scad` / `update_scad_body` / `create_from_scad`) unchanged**: confirmed independent (zero cross-imports with the reconstruction chain).
- **D7 — Tests-after, not TDD**: this is a removal/refactor (no new behavior to spec); the refactored consumers keep happy + failure boundary tests.
- **D8 — Single atomic commit on master**: history preserved; no `git rebase`; no intermediate commits; the F4 verifier asserts clean tree post-commit.

## Scope

### In scope

Atomic dismantle of the 1-shot mesh-reconstruction MCP tools and their backend strategy code, while preserving reusable Python primitives and stripping only the strategy assumptions baked into foundational tool output.

Five `mcp_server/` Python files edited, 4 test files deleted/updated/refactored, one `.md` updated, single atomic commit on `master`.
